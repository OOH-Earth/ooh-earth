### Architecture decision (Step 2)
Considered and rejected a fully-centralized approach (monkey-patching `base44.entities.<Entity>.subscribe` generically inside `base44Client.js`, driven by a module-level flag AuthContext would set). Rejected because: (a) it requires wrapping SDK internals generically (a `Proxy` or per-entity enumeration), more fragile against SDK upgrades and harder to reason about than direct code; (b) critically, it does **not** solve "auth transition" correctly by itself — an already-mounted component's effect has already run by the time a shared flag changes, so login/logout would still need some reactive signal reaching every component, which means re-inventing React's own effect-dependency reactivity from scratch inside a non-React module singleton. Chose instead: **one small shared hook** (`useAuthGatedSubscribe`) that every call site calls directly, reusing the app's *already-correct, already-tested* `useAuth()` reactivity (`authChecked`/`isAuthenticated` from `AuthContext.jsx`) rather than building a second one. This touches more files (14) than a true central patch would, but each touch is a small, uniform, low-risk swap, and the actual gating *logic* has exactly one implementation, not 14 copies. Explicitly followed the task's own permission for "smallest understandable per-call-site approach" over a mechanically-centralized one where centralization would add risk.

### AuthContext.jsx semantics read in full (Step 3)
`authChecked` becomes `true` exactly once after the app's initial auth bootstrap resolves (success or failure) and **never resets to `false`**, including on `logout()` — it means "has the app ever finished checking," not "is a check currently in flight." `isAuthenticated` is the real gate. `logout(shouldRedirect=true)` (the default, used everywhere in this codebase) navigates away via `base44.auth.logout(url)`, so in practice most logouts are a full page unload (subscriptions torn down by the browser itself, not by React); the hook still handles a same-page `isAuthenticated→false` transition correctly regardless (its effect depends on `[authChecked, isAuthenticated, entityName]`), since that path exists in the API (`logout(false)`) even if the current UI doesn't call it directly.

- **New**: `src/hooks/authGatedSubscribeCore.js` — pure, dependency-free (`shouldOpenSubscription(authChecked, isAuthenticated, entityName)`, `subscribeToEntity(entities, entityName, callback)`).
